# MEX 0.9.0 release preparation

0.9.0 ships in three steps: `0.9.0-beta.1`, `0.9.0-beta.2` and `0.9.0`. The betas go to the npm `next` tag and to GitHub pre-releases. `latest` stays on 0.8.5 until 0.9.0. This file records each step; beta.1 comes first.

## 0.9.0-beta.1

### Scope and base

- **Base:** `next` at `798de9dd`, plus the fixes below. Nothing from `next2` is included: the output levers and the seven additional agents ship later.
- **Agents:** Claude Code and Codex.

**What a person gets:**
- **Install and setup:**
  - one machine-wide install;
  - `mex` in a repo in seconds at $0;
  - an honest first screen with what to do next and how to undo it.
- **Notes:**
  - `mex note`, checked when saved;
  - notes in each agent's own rule files and in the session-start brief;
  - a note held back, or pointed at the current code, once the code makes it false.
- **Team:**
  - `mex share` to a git branch;
  - upgrade from 0.8.
- **Control:**
  - `mex off` and `mex uninstall`, exactly reversible;
  - `mex doctor`.
- **Learning from what people type is off by default.** It is opt-in with `mex config set learning.statements on`.

### Functional test (17 Nov 2026)

**Setup:** isolated homes on Windows 11 and WSL Ubuntu, using Claude Code 2.1.326 and Codex 0.165.

**Labels:** measured means run once on the named sample; counted means exact.

- **Tell it once (live, measured):** 6 notes, then a new session that may not use tools.
  - Claude Code (Haiku) answered all 6 correctly, for $0.0018.
  - Codex (gpt-6-luna) answered all 6 correctly, using 5,303 tokens.
- **Never stale (live, measured):** a commit changed `PORT` from 3000 to 4000.
  - MEX held the note back on both agents.
  - Claude answered 4000 and said the old note was flagged.
  - Codex answered "unknown".
  - The rule file was rebuilt without the note.
- **Knowledge bench (counted, $0, deterministic):** 46 claims over 6 real Hono history checkpoints.
  - No stale claim was delivered in full at any checkpoint, while 3, 5, 9, 14 and 15 stale claims existed at C1 to C5.
  - Of the still-true claims at C5, 20 of 31 went out in full; the rest went out as a pointer to the current code or were held back.
- **Upgrade (counted):** four real 0.8 repositories all reach a ready preview. One was applied (44 entries).
- **Install:** the global npm install works through the symlink on Linux, and uninstall restores exactly.

### Fixes found by that test

- **Setup and install:**
  - Install and the background launcher work through npm's `bin/mex` symlink on Linux and macOS.
  - The first screen no longer reports false "out of date" rule lines: on novu, 16 of 17 were false.
  - MEX's rule files are written before the first session in a fresh repo, and setup's test and build commands become checked entries.
- **Delivery and freshness:**
  - A note the code made false no longer reaches the agent through MEX's rule files, and a personal fact is pointed at the current code instead of restated.
  - A prompt that names a file no longer swallows that file's pitfall.
  - `mex off` now also removes MEX's own rule files in that repo.
- **The person's own words:**
  - The command gate keeps a person's sentence around a real command.
  - The memory filter keeps the words of a note someone wrote.
  - The judge never rewrites such a note; its proposed wording goes to `mex review`.
- **Upgrade:** two of four real repos were blocked. Root-only groundings no longer block, an unreadable document stays in place for review, and the preview is now a summary plus a file list.

### Known limits

- **The start brief** holds about 300 bytes, so 1–2 notes; more reach the agent through MEX's rule files.
- **Notes scoped to a path** are corrected at their next delivery moment, not at session start.
- **Hook overhead on a Windows laptop** is about 7–15 ms per call on top of the agent's own process start (measured). The release gate's 17 ms bound is judged on CI runners.
- **No savings or task-success claim.** The full pre-registered run follows 0.9.0.

### Release steps

1. Set the version to `0.9.0-beta.1`, then run `node scripts/build-hook-binaries.mjs` to sync the six `npm/hook-*` manifests.
2. Open a pull request into `next`. `ci-passed` and the release workflow's three-OS install smoke must pass.
3. Merge, then push the tag `v0.9.0-beta.1`. The tag run checks the beta.1 gates (knowledge bench, hook timing, three-repo upgrade) on three operating systems, builds and smoke-tests the seven packages, then waits for approval on `npm-publish`.
4. After publishing:
   - `npm view mex-agent dist-tags` shows `next: 0.9.0-beta.1` and `latest: 0.8.5`;
   - a clean install passes install, first screen and a note in a new session.
