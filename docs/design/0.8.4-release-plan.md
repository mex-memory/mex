# MEX 0.8.4 release preparation

Release branch: `codex/release-0.8.4`, based on main
`54f7d7a538bd0c77abf21484893bee74f4c0bb68`, with the terminal setup work in
`5a9035eed696d5e282004a892e8aaef3e026eb48` and the default-routing follow-up.
Preparation started October 9, 2026. The maintainer selected 0.8.4 and authorized
release preparation and a PR. This is an unpublished release; merge, tagging,
npm publication, and a GitHub release are separate actions.

## Scope

The previous release is [v0.8.3](https://github.com/mex-memory/mex/releases/tag/v0.8.3),
at `8a1e39b1e52e92b40b203da411b54cc955a256aa`. Its GitHub publication timestamp is
September 27, 2026 UTC (September 28 in the maintainer's timezone).

0.8.4 includes the changes since that tag, including the Graph/Wiki performance,
grounding, search, and knowledge-adoption changes already on main. The PR adds
terminal setup as the default, the spaced lowercase cyan banner, native agent
handoff, real graph activity, resumable outcomes, authored setup errors, and
the release metadata and documentation. The packaged smoke follows the new
noninteractive setup contract instead of answering removed numeric prompts.

Current package versions, capability fixtures, installation examples, and
release links move to 0.8.4. Historical changelog and design records retain
their original versions. Private workspace versions, dependency versions, and
installed-skill provenance are independent of the published CLI version.
Unrelated managed-skill edits, local `.mex/config.json`, and Discord artwork
remain outside the PR.

## Compatibility and remaining work

Upgrade every collaborator before committing new `mh2:` groundings: 0.8.3 and
earlier clients cannot read that encoding. Preserve the existing graph for the
first refresh, review changes through `mex check` and `mex sync`, and rebuild
the Wiki index when needed. See [COMPATIBILITY.md](../../COMPATIBILITY.md) for
the exact upgrade sequence and additive public API changes already on main.
The maintainer's explicit 0.8.4 selection is a release-specific exception to
the usual minor-version policy for additive public fields.

The setup presentation and diagnostics do not fix large-repository compiler
heap exhaustion. Browser setup's existing readiness shortcut can also offer
completion after a failed finalization if its placeholder/index-presence checks
pass; oversized population prompts can exceed the private run-response limit.
Those remain follow-ups and must not be represented as solved by this release.
Fresh-project interview changes remain outside this work.

### PR #271 CI follow-up

The [first PR run](https://github.com/mex-memory/mex/actions/runs/37973046420)
at `8fc1449` passed Node 24, macOS portability, browser, and release-performance
checks. Two test assumptions failed:

- Node 22 passed 4,746 tests but failed an entry-discovery non-mutation snapshot
  because `.git/objects/maintenance.lock` disappeared. Fixture commits could
  leave automatic Git maintenance running after the commit returned. The test
  helper now passes command-scoped `maintenance.auto=false`; the full project
  and Git-byte snapshots remain intact. A local Git trace confirmed the default
  fixture commit launched detached maintenance and the override prevented it.
- Windows portability passed 545 tests but the abrupt graph-worker death case
  expected POSIX `SIGKILL`. The test now requires a nonzero numeric exit code
  with a null signal on Windows, and `SIGKILL` with a null exit code on POSIX.
  It also checks that the worker is dead, retaining workspace/sidecar cleanup
  and unchanged-live-graph assertions.

The fix changes tests and documentation only. Focused local tests passed on
Node 22.17.1/macOS (eight entry cases and 20 candidate-process cases), followed
by the root and both Hub workspace typechecks. Exact Windows and Linux/Git
runner verification remains a gate in the next PR run; production behavior,
protocols, resource limits, and build outputs are unchanged.

### PR #271 review fixes

The Windows review identified a pending stdin read after native handoff, a
short-path/case mismatch in packed CLI discovery, an unrealistically short
malformed-worker startup deadline, and Wiki grounding refusing a stable graph
solely because an unrelated file parsed incompletely. Follow-up findings covered
stale completion text after a browser commit, vanished migration notices,
Finish later reporting failure, narrow footer/link usability, and a cleanup
signal presented as the worker failure's cause.

Terminal close now pauses and unrefs stdin. A real-PTY copy-link round trip
also exposed readline's paused input stream after returning to the HUD. Manual
prompt/link questions keep the cooked terminal without its keypress decoder;
the remounted HUD resumes reads after installing its input handler.
`l` prints the full Hub URL outside the frame; footer variants fit the available
width. Details retain at most 64 events, 1,024 characters each, and 16,384 total,
open at the current diagnostic, and permit scrolling back. Finish later clears
the prior population failure for its explicit paused outcome, and stopping the
Hub rechecks the commit readiness before selecting the final message. Worker
diagnostics retain the actual signal and mark supervisor cleanup separately.

Only the Wiki grounding bridge admits parse-only graph degradation. It filters
nodes, symbols, fingerprints, and source evidence to fully parsed files, abstains
from missing-target reconciliation, and names the incomplete files. Source and
configuration drift still refuse; final snapshot/source revalidation still
discards a prepared publication on change. General GraphPort reads keep their
existing stricter gate. Public exports and protocol/index schemas are unchanged.

The [second PR run](https://github.com/mex-memory/mex/actions/runs/37975590426)
